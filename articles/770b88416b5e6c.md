# はじめに

皆さんはPCを買い替えたときのセットアップをどうしていますか？

- Homebrewやaptで必要なパッケージをインストールする
- 開発に使うGitリポジトリをcloneする
- dotfilesを配置する
- シェルでmiseを有効にする
- Node.jsやPythonなどをインストールする
- Gitなどの初期設定を行う

このような作業を手順として残していても、新しいPCで最初から実行するのはなかなか大変です。
`mise bootstrap`を使うと、これらのセットアップを`mise.toml`に定義し、まとめて実行できます。

:::message
この記事は[mise v2026.8.3](https://github.com/jdx/mise/releases/tag/v2026.8.3)の公式ドキュメントを基準にしています。`mise bootstrap`は[v2026.7.4](https://github.com/jdx/mise/releases/tag/v2026.7.4)で安定版になったため、それより前のバージョンでは実験的機能の有効化が必要です。
:::

# mise bootstrapとは

以前の記事では、miseを使ってNode.jsやPythonなどのバージョンを管理する方法を紹介しました。
https://zenn.dev/takuty/articles/975dd7e886fff6

`mise install`は`[tools]`に定義された開発ツールをインストールしてくれますが、`mise bootstrap`はさらに次のようなセットアップも行ってくれます。

- パッケージのインストール
- 開発に使うGitリポジトリのclone
- dotfilesの配置
- miseをシェルで有効にする設定
- 最後に行いたい独自タスクの実行

また、すでに目的の状態になっているパッケージやファイルなどはスキップされます。
初回のセットアップだけではなく、後から設定を追加したときも、同じコマンドで定義した状態に更新できます。

# セットアップ内容を定義する

今回はdotfilesリポジトリに`mise.toml`と設定ファイルをまとめて管理するという想定で進めます。
新しいPCでは、このdotfilesリポジトリを最初にcloneしてから`mise bootstrap`を実行する流れになります。

```text
dotfiles/
├── mise.toml
└── .editorconfig
```

`mise.toml`にセットアップすべき内容を記述します。

```toml:mise.toml
# パッケージマネージャーで管理するパッケージ群
[bootstrap.packages]
"brew:git" = "latest"
"brew:jq" = "latest"

# 必要であれば開発に使うリポジトリもcloneできる
[bootstrap.repos]
"~/src/github.com/your-name/sample-app" = { url = "https://github.com/your-name/sample-app.git", ref = "main" }

# ホームディレクトリへ配置する設定ファイル
[dotfiles]
"~/.editorconfig" = { source = ".editorconfig", mode = "copy" }

# zshの起動時にmiseを有効化する
[bootstrap.mise_shell_activate]
zsh = true

# miseで管理する開発ツール
[tools]
node = "24.0.1"
python = "3.13.3"

# 最後に実行するプロジェクト固有の処理
[tasks.bootstrap]
run = "git config --global init.defaultBranch main"
```

## パッケージ

`[bootstrap.packages]`には、OSのパッケージマネージャーでインストールしたいものを`マネージャー:パッケージ名`の形式で指定します。

```toml
# brewを使う場合
[bootstrap.packages]
"brew:git" = "latest"
```

Ubuntuで`apt`を使う場合は、マネージャー名を置き換えます。

```toml
# aptを使う場合
[bootstrap.packages]
"apt:git" = "latest"
```

現在のOSで利用できないマネージャーの定義は適用されません。

`apt`などはOSに用意されたパッケージマネージャーを利用します。一方、`brew`と`brew-cask`はmiseに組み込まれたインストーラーを利用するため、Homebrew本体を別途インストールする必要はありません。

:::message
対応しているパッケージマネージャーやバージョン指定の可否は異なります。利用するマネージャーごとの公式ドキュメントを確認してください。
:::

`[tools]`と`[bootstrap.packages]`のどちらでどのツールを管理するか、整理を決めておくのがおすすめです。

私は次の基準で使い分けています。

- `[tools]`: Node.jsやPythonのようにプロジェクトごとにバージョンを管理したいツール
- `[bootstrap.packages]`: gitやjqのようにマシン全体で利用したいツール

https://mise.jdx.dev/bootstrap/packages/

## 開発に使うGitリポジトリをcloneする

`[bootstrap.repos]`には、clone先のパスとリポジトリURLを指定します。
dotfilesリポジトリ自体は最初に手動でcloneするため、ここでは他に開発で必要なリポジトリを定義します。

```toml
[bootstrap.repos]
"~/src/github.com/your-name/sample-app" = { url = "https://github.com/your-name/sample-app.git", ref = "main" }
```

`ref`にはbranch、tag、完全なcommit SHAを指定できます。

指定したディレクトリにリポジトリがなければcloneされ、すでに存在する場合はoriginや`ref`が確認されます。
ローカルに変更が残っているリポジトリを勝手にリセットすることはありません。

`ref`を省略した既存のリポジトリは自動ではpullされません。明示的に更新したい場合は`mise bootstrap repos update`を利用します。

複数の開発リポジトリを決まったディレクトリへまとめてcloneしたい場合に便利です。
必要なければ`[bootstrap.repos]`は定義しなくても問題ありません。

https://mise.jdx.dev/bootstrap/repos.html

## dotfilesを配置する

`[dotfiles]`では、同じリポジトリに置いた設定ファイルをホームディレクトリへ配置できます。

```toml
[dotfiles]
"~/.editorconfig" = { source = ".editorconfig", mode = "copy" }
```

相対パスで指定した`source`は、`mise.toml`が置かれているディレクトリを基準に解決されます。
この例では、同じdotfilesリポジトリ内の`.editorconfig`を`~/.editorconfig`へコピーします。

`copy`以外にも、シンボリックリンクを作成する`symlink`や、環境ごとに内容を変えられる`template`なども利用できます。

`symlink`で既存の管理外ファイルと競合した場合は、デフォルトでは上書きせずエラーになります。一方、`copy`と`template`は対象ファイルの内容を上書きします。今回の例で既存の`~/.editorconfig`を残したい場合は、実行前に退避してください。

https://mise.jdx.dev/dotfiles.html

## miseをシェルで有効にする

`[bootstrap.mise_shell_activate]`を定義すると、bash、zsh、fishの起動ファイルへmiseを有効にする設定を追加できます。

```toml
[bootstrap.mise_shell_activate]
zsh = true
```

`zsh = true`を指定すると、次の設定が追加されます。

```text
~/.zprofile → eval "$(mise activate zsh --shims)"
~/.zshrc    → eval "$(mise activate zsh)"
```

miseが管理するマーカー内だけを更新するため、すでに記述している他の設定はそのまま維持されます。

:::message
`[dotfiles]`で`~/.zprofile`や`~/.zshrc`全体を管理している場合、同じファイルに対するシェル有効化の設定はスキップされます。その場合は、管理しているファイルへ有効化の設定を直接記述してください。
:::

https://mise.jdx.dev/bootstrap/shell.html

## 開発ツールと最後のタスク

`[tools]`は通常のmiseと同じように、Node.jsやPythonなどのバージョンを定義します。
bootstrapの途中で`mise install`が実行され、足りないツールをインストールしてくれます。

```toml
[tools]
node = "24.0.1"
python = "3.13.3"
```

また、`bootstrap`という名前のタスクを定義しておくと、最後に`mise run bootstrap`が実行されます。
Gitの初期設定など、用意されている機能に当てはまらないセットアップに利用できます。

```toml
[tasks.bootstrap]
run = "git config --global init.defaultBranch main"
```

:::message alert
パッケージやdotfilesは設定済みであればスキップされますが、`tasks.bootstrap`は毎回実行されます。
冪等性が担保されるコマンドのみを指定してください。
:::

# bootstrapでセットアップしてみる

dotfilesリポジトリをcloneして、そのディレクトリに移動したら、最初に設定ファイルを信頼させます。

```bash
mise trust
```

いきなりセットアップせず、まずは`--dry-run`で何が行われるか確認してみます。

```bash
mise bootstrap --dry-run
```

内容に問題がなければ、セットアップを実行します。

```bash
mise bootstrap
```

確認を省略したい場合は`--yes`も指定できます。

```bash
mise bootstrap --yes
```

これだけでOSパッケージ、開発リポジトリ、dotfiles、シェル設定、開発ツール、最後のタスクまで順番にセットアップしてくれます。

# 現在の状態を確認する

定義した内容が現在のマシンに反映されているかは、`status`で確認できます。

```bash
mise bootstrap status
```

不足や差分があるときに終了コード1を返してほしい場合は`--missing`を利用できます。

```bash
mise bootstrap status --missing
```

また、一部だけを実行したい場合は`--only`、一部を除外したい場合は`--skip`も利用可能です。

```bash
# dotfilesだけを適用
mise bootstrap --only dotfiles

# 最後のbootstrapタスクを実行しない
mise bootstrap --skip task
```

# 他にもできること

今回は開発マシンのセットアップに絞って紹介しましたが、v2026.8.3の`mise bootstrap`では他にも次のような設定を管理できます。

- macOSのDock、Finder、キーボードなどの設定
- macOSのLaunchAgents
- Linuxのユーザーとグループ
- root権限が必要なファイルやディレクトリ
- systemdのシステムサービス
- Linuxのsystemdユーザーサービスとtimer
- Linuxのホストファイアウォール
- Docker Composeプロジェクト
- 秘密値を利用した設定ファイルの生成
- SSH経由でのリモートホストへの適用

開発マシンだけでなく、Linuxサーバーも同じ仕組みでセットアップできます。`mise.toml`を起点に、端末やサーバーの設定をまとめて管理できるのは便利ですね。

Linuxサーバー向けの機能は[v2026.8.2](https://github.com/jdx/mise/releases/tag/v2026.8.2)で追加されました。

# まとめ

`mise bootstrap`を使うことで、これまで手作業で行っていた開発マシンのセットアップを`mise.toml`にまとめることができました。

設定を一度用意しておけば、miseをインストールしてdotfilesリポジトリに移動した後は、次のコマンドだけで環境を再現できます。

```bash
mise trust
mise bootstrap --dry-run
mise bootstrap
```

dotfilesと`mise.toml`を同じリポジトリに置いておくことで、マシンの設定とセットアップ手順をまとめて管理できます。
まずはOSパッケージ、`[dotfiles]`、`[tools]`だけでも定義しておくと、新端末のセットアップ負荷がかなり楽になります。
miseで「このPCには何をインストールするんだっけ？」と悩む必要もなくなるので、ぜひ試してみてください。
